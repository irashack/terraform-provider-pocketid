# Pocket ID provider for Terraform and OpenTofu

Manage [Pocket ID](https://pocket-id.org/) OIDC clients and their secrets, users,
groups, APIs and instance settings as code. This is an independent provider. It
began in September 2026 as a maintenance fork of
[Trozz/terraform-provider-pocketid](https://github.com/Trozz/terraform-provider-pocketid)
and has been its own project since 2026-10-02, with its own version numbers and no
tracking of upstream. Release **3.0.1**, its first as an independent project (3.0.0
was tagged but never released; 3.0.1 is the same provider with a test-fixture fix),
supports Pocket ID **2.14.0 through 2.18.0**. Its archives are published on
[GitHub releases](https://github.com/irashack/terraform-provider-pocketid/releases)
and installed through the native filesystem mirror in [INSTALL.md](INSTALL.md) under
the source address `registry.terraform.io/irashack/pocketid`; it is not published to a
provider registry. It has deliberate breaking changes from 2.4.x, each marked
**Breaking** in the 3.0.0 section of [CHANGELOG.md](CHANGELOG.md). This is not an
official Pocket ID or Trozz release.

## Get started

Install the verified archive as [INSTALL.md](INSTALL.md) describes before running
`terraform init` or `tofu init`; a GitHub release alone does not make the provider
registry-installable. If you already use this provider, read
[Upgrading from 2.4.x](#upgrading-from-24x) first.

```hcl
terraform {
  required_providers {
    pocketid = {
      source  = "registry.terraform.io/irashack/pocketid"
      version = "3.0.1"
    }
  }
}

# Supply POCKETID_BASE_URL and POCKETID_API_TOKEN through your environment.
provider "pocketid" {}

resource "pocketid_client" "example" {
  name          = "Example application"
  callback_urls = ["https://app.example.com/oauth/callback"]
}
```

Create an API key in your Pocket ID instance and supply it through your secret
manager or local environment. The base URL is the instance origin, such as
`https://id.example.com`, without `/api`. Keep API keys out of `.tf` files.
A generated client secret is a sensitive value stored in state; with
`generate_secret = false` and a write-only `pocketid_client_secret` none is.
Protect state and saved plans.

Already using `trozz/pocketid`? See
[Moving from upstream's provider](UPSTREAM.md#moving-from-upstreams-provider) and
the [state migration procedure](INSTALL.md#existing-upstream-managed-resources),
and require a plan with no replacements or secret rotation. Keep this provider's
own address; do not overwrite an upstream binary or use development overrides for
normal installations.

## What you can manage

Each name links to its generated documentation, which lists every attribute. Where
a secret has a write-only input, its `_wo` attribute is paired with a `_wo_version`
string (see [Conventions](#conventions)); write-only attributes need Terraform or
OpenTofu 1.11 or later. This table is the complete list: every resource and data
source the provider has is in `docs/`.

### Clients and secrets

| Resource | Purpose | Notable attributes |
|---|---|---|
| [`pocketid_client`](docs/resources/client.md) | An OIDC client: callback and logout URLs, public or confidential, PKCE, pushed authorization requests, back-channel logout (Pocket ID 2.17.0 or later), federated identities, group restriction | `generate_secret`; computed sensitive `client_secret` and `client_secret_id`; `allowed_user_groups` (a set) with `is_group_restricted`; `unresolved_creation` |
| [`pocketid_client_secret`](docs/resources/client_secret.md) | One secret of a client, rotated without replacing the client (Pocket ID 2.14.0 or later) | Sensitive `secret` generated by Pocket ID, or write-only `secret_wo` with `secret_wo_version`; `expires_at` |
| [`pocketid_client_logo`](docs/resources/client_logo.md) | A client's light or dark logo, uploaded from a local file or an icon of Pocket ID's icon library (2.18.0 or later) | `variant`, `source` or `preset`, computed `sha256` |

### Users, groups and membership

| Resource | Purpose | Notable attributes |
|---|---|---|
| [`pocketid_user`](docs/resources/user.md) | A user account (the user registers a passkey in the Pocket ID web interface) | `groups` and `custom_claims` (authoritative); optional chosen `id`; `unresolved_creation` |
| [`pocketid_user_profile_picture`](docs/resources/user_profile_picture.md) | A user's profile picture, uploaded from a local file | `source`, computed `sha256` and `stored_sha256` |
| [`pocketid_group`](docs/resources/group.md) | A user group | `friendly_name`, `custom_claims` |
| [`pocketid_group_membership`](docs/resources/group_membership.md) | Adds one user to one group, without owning the group's other members | `unresolved_creation` |
| [`pocketid_group_members`](docs/resources/group_members.md) | Owns a group's whole membership | `user_ids`; `unresolved_user_ids` |
| [`pocketid_one_time_access_token`](docs/resources/one_time_access_token.md) | A one-time sign-in token for a user | `ttl`; sensitive `token` |

For one group, do not combine `pocketid_group_members` with
`pocketid_group_membership`, a second `pocketid_group_members` or the `groups`
attribute of a `pocketid_user` that is, or should be, a member.

| Resource | Purpose | Notable attributes |
|---|---|---|
| [`pocketid_scim_service_provider`](docs/resources/scim_service_provider.md) | The SCIM provisioning target of one client | `token`, or write-only `token_wo` with `token_wo_version` |
| [`pocketid_scim_sync`](docs/resources/scim_sync.md) | Runs a SCIM synchronization during the apply | `service_provider_id`, `triggers` |
| [`pocketid_ldap_sync`](docs/resources/ldap_sync.md) | Runs an LDAP synchronization during the apply | `triggers` |
| [`pocketid_signup_token`](docs/resources/signup_token.md) | A token that lets people register, optionally into groups | `ttl`, `usage_limit`, `user_group_ids`; sensitive `token`; `expired` |

### APIs and grants

| Resource | Purpose | Notable attributes |
|---|---|---|
| [`pocketid_api`](docs/resources/api.md) | A protected resource clients request access tokens for (Pocket ID 2.14.0 or later) | `resource`, `permissions` (a map), `allow_cimd_clients` |
| [`pocketid_api_client_access`](docs/resources/api_client_access.md) | One client's access to one API, user-delegated and client-credentials, each with permission keys (Pocket ID 2.14.0 or later) | `user_delegated_access`, `client_access`, `user_delegated_permissions`, `client_permissions` |

### Application configuration and images

| Resource | Purpose | Notable attributes |
|---|---|---|
| [`pocketid_application_config`](docs/resources/application_config.md) | The instance's global settings (one per instance); an omitted setting stays as the server has it | `smtp_password_wo` and `ldap_bind_password_wo` with their `_wo_version`; plain `smtp_password` and `ldap_bind_password` (sensitive) |
| [`pocketid_application_image`](docs/resources/application_image.md) | One of the application images (logos, e-mail logo, background, favicon, default profile picture), uploaded from a local file | `kind`, `source`, computed `sha256` |

### Read-only data sources

| Data source | Purpose |
|---|---|
| [`pocketid_client`](docs/data-sources/client.md), [`pocketid_clients`](docs/data-sources/clients.md) | One client by `id`, or all clients, including federated identities and each client's secrets (ID, prefix and times, never a value) |
| [`pocketid_user`](docs/data-sources/user.md), [`pocketid_users`](docs/data-sources/users.md) | One user by exactly one of `id`, `username` or `email`, or all users |
| [`pocketid_current_user`](docs/data-sources/current_user.md) | The user the provider's API key belongs to |
| [`pocketid_user_passkeys`](docs/data-sources/user_passkeys.md) | A user's passkeys, with no credential material |
| [`pocketid_group`](docs/data-sources/group.md), [`pocketid_groups`](docs/data-sources/groups.md) | One group by `id` or exact `name`, or all groups, with `member_ids` and `allowed_client_ids` |
| [`pocketid_api`](docs/data-sources/api.md), [`pocketid_apis`](docs/data-sources/apis.md) | One API by `id` or `resource`, or all APIs, with their permissions |
| [`pocketid_signup_tokens`](docs/data-sources/signup_tokens.md) | The valid signup tokens, never their values |
| [`pocketid_api_keys`](docs/data-sources/api_keys.md) | The provider key owner's API keys (never a value), for a `check` block that warns before the key expires |
| [`pocketid_application_config`](docs/data-sources/application_config.md) | The instance settings, without `smtp_password` or `ldap_bind_password` |
| [`pocketid_version`](docs/data-sources/version.md) | The Pocket ID server's version, for preconditions |
| [`pocketid_logo_presets`](docs/data-sources/logo_presets.md) | Icons of Pocket ID's icon library matching a search (2.18.0 or later), for `preset` on `pocketid_client_logo` |

Deliberately not offered: creating, renewing or revoking API keys, and creating or
deleting passkeys (a lockout risk; passkeys can be listed). See
[examples](examples/README.md) for complete configurations and
[provider settings](docs/index.md) for authentication, TLS and timeouts.

## Conventions

These apply across resources. Each resource's documentation names the attributes.

1. **Write-only secrets (`_wo` and `_wo_version`).** Where a secret can be sent
   without being stored, a pair of attributes holds it: `<name>_wo` (write-only,
   sensitive) and `<name>_wo_version` (a string). These are `smtp_password_wo` and
   `ldap_bind_password_wo` on `pocketid_application_config`, `token_wo` on
   `pocketid_scim_service_provider`, and `secret_wo` on `pocketid_client_secret`.
   The value is sent when the resource is created and whenever you change the
   version string; it never enters plan or state, so it can come from an ephemeral
   value, and a change made to the secret outside Terraform is not detected. The
   first three conflict with the plain attribute that stores the secret in state
   (`smtp_password`, `ldap_bind_password`, `token`), which works with any Terraform
   or OpenTofu version; `secret_wo` supplies a value that Pocket ID would otherwise
   generate. Write-only attributes need Terraform or OpenTofu 1.11 or later.
2. **Unmanaged unless set.** A setting you leave out is left as the server has it,
   state shows the server's value, and an unrelated update shows no change for
   it. Setting it makes it authoritative. This covers `description`,
   `skip_consent`, `launch_url` and the two token lifetimes on `pocketid_client`
   (set `description = ""` or `launch_url = ""` to remove one) and every
   setting you omit from `pocketid_application_config`. Attributes that
   describe a complete set, such as a user's `groups` and `custom_claims`, stay
   authoritative: omitted means none.
3. **Confirmed absence.** A client, user, group or SCIM service provider leaves
   state, and its destruction succeeds, only when Pocket ID answers that exact
   object does not exist, in its own structured not-found error. Any other 404
   (a wrong `base_url`, a proxy's error page) stays an error, so a
   misconfiguration cannot make resources vanish from state.
4. **Verify what the server did.** Pocket ID silently ignores some input, such
   as a group ID that names no group, so after a write the provider compares
   what the server holds with what was asked and fails naming the difference. It
   does this for group IDs (`allowed_user_groups`, `pocketid_user.groups`,
   `pocketid_group_membership`, `pocketid_signup_token.user_group_ids`), the user
   IDs of `pocketid_group_members`, custom claims, the grant in
   `pocketid_api_client_access` (permission keys are checked before the write),
   and the settings in `pocketid_application_config`.
5. **State compatibility.** New attributes decode from state written by 2.4.103
   and 2.4.104 without a state upgrader, and an unchanged configuration plans
   empty afterwards, except for the changes the changelog marks as breaking or as
   one-time. The native upgrade scripts in [TESTING.md](TESTING.md) prove this
   against a real server.

## Differences from upstream

[UPSTREAM.md](UPSTREAM.md) has the history, each difference in detail, how
upstream's behavior was established, and what independence means for issues and
contributions. Upstream's behavior is described below only where UPSTREAM.md
records it. What this provider does that upstream does not, or does differently:

- **More resources.** Upstream's main branch (6f55403, checked 2026-10-03)
  registers seven resources (`client`, `user`, `group`, `one_time_access_token`,
  `application_config`, `scim_service_provider`, `ldap_sync`) and seven data
  sources (`client`, `clients`, `user`, `users`, `group`, `groups`,
  `application_config`). This provider adds ten resources: `client_secret`,
  `client_logo`, `user_profile_picture`, `group_membership`, `group_members`,
  `scim_sync`, `signup_token`, `api`, `api_client_access` and `application_image`;
  and seven data sources: `current_user`, `user_passkeys`, `api`, `apis`,
  `api_keys`, `signup_tokens` and `version`. The ones both have behave differently,
  as below.
- **Redirects and retries.** Redirects are never followed with the API key.
  Changes (create, update, delete, uploads) are never retried; reads are retried
  up to four attempts, each one request on a fresh connection. Upstream retries
  POST, PUT and DELETE after a server error or a connection reset, which can leave
  an orphaned secret or a duplicate object. Lists of users, groups and clients are
  read completely, not as the first page.
- **Secrets stay contained.** No secret reaches a log, a diagnostic or
  non-sensitive state. Errors and logs never contain a response body, reason
  phrase or malformed-response text. The admin API key is kept out of every value
  the provider stores, logs or shows, apart from the secret values that go only to
  sensitive state: an identifier, base URL or request text carrying it is refused
  before any request, an answer carrying it is not used, no configured text is
  logged, and plan-time messages name the attribute and rule, never the configured
  value. The `pocketid_signup_tokens` and `pocketid_api_keys` data sources never
  expose a token or key value.
- **Write-only secret inputs.** `smtp_password_wo`, `ldap_bind_password_wo`,
  `token_wo` and `secret_wo` keep secrets out of plan and state
  ([Conventions](#conventions)). `pocketid_client.client_secret` is computed, not
  configurable as in upstream's #90; a custom or rotating secret is a separate
  `pocketid_client_secret`, and `generate_secret = false` keeps `pocketid_client`
  from holding one. The secret Pocket ID 2.17.0 creates with a new confidential
  client is revoked, so the client holds exactly the secret in state.
- **Verification and fail-closed access control.** After a write the provider
  compares what the server holds with what was asked (Convention 4). Group
  restriction fails closed: `is_group_restricted` is explicit, removing a client's
  groups leaves it admitting nobody, opening a restricted client needs
  `is_group_restricted = false`, and a group ID that names no group fails the
  apply. For a user or group Pocket ID synchronizes from LDAP, an update it would
  silently ignore fails before anything is written.
- **Unresolved outcomes are marked, not guessed.** When a change may or may not
  have been made, the provider does not repeat it. A create whose answer named no
  usable object records nothing (for client secrets, APIs and signup tokens the
  error says what Pocket ID holds now), and one that named the new object keeps
  only its validated ID, tainted. Where the outcome stays ambiguous the resource is
  marked: `unresolved_creation` on `pocketid_user` and `pocketid_client` (when `id`
  or `client_id` was chosen) and on `pocketid_group_membership`,
  `unresolved_user_ids` on `pocketid_group_members`, and an unresolved grant on
  `pocketid_api_client_access`. A marked resource refuses the changes that could
  act on the wrong object until a refresh, or you, resolve it. A failed rollback is
  reported, not hidden: upstream discards the cleanup delete's error and reports
  the object as deleted. The recovery steps (`terraform state rm`, then
  `terraform import` or another ID) are in the changelog's "When a result is
  uncertain".
- **Clients, users and application configuration.** `client_id` always equals the
  client's real ID. Federated identities keep `replay_protection` and
  `public_keys`, and `backchannel_logout_url` is managed; upstream's client update,
  as examined on 2026-10-02, resets the first two and clears a back-channel logout
  URL set in the admin UI. A client's logo is the `pocketid_client_logo` resource.
  A user holds exactly the configured `groups` and `custom_claims`, can be created
  with a chosen `id` (never changed afterward), and plan-time validators follow
  Pocket ID's own rules. `pocketid_application_config` sends back every setting
  Pocket ID reports, including ones this version does not know, and checks values
  at plan time and after the write.
- **State compatibility from 2.4.104.** State written by 2.4.103 and 2.4.104 keeps
  working under the same source address, with no `state replace-provider` and no
  state upgrader, and plans empty except for the documented breaking and one-time
  changes ([INSTALL.md](INSTALL.md#upgrade-from-24104-to-301)); from older
  releases, upgrade to 2.4.104 first. The only upstream state this project has run
  against is upstream 2.3.0 on Pocket ID 2.13.0; later upstream state is untested.
- **Supported versions and test matrix.** Pocket ID 2.14.0 through 2.18.0 is
  supported, at the exact versions the acceptance suites run against on official
  images ([Compatibility](#compatibility-and-current-limits)). Native proofs run a
  real `terraform` and a real `tofu` binary against a disposable server, including
  upgrades from the published 2.4.104 archive ([TESTING.md](TESTING.md)).
- **Independent versioning.** 3.0.0 is this project's own number. This project's
  2.4.0 and 2.4.1 already shared numbers with upstream releases of the same name but not
  their content, and a 3.x release of either project says nothing about the other.
  The Go module is `github.com/irashack/terraform-provider-pocketid` (upstream's
  path until 3.0.0).

## Compatibility and current limits

Pocket ID **2.14.0 through 2.18.0** is supported, at the exact patch versions the
acceptance suites run against (official images). Untested patch versions are not
automatically certified. **2.13.0 and earlier are not supported or tested**; legacy
parsing safeguards, such as the singular secret endpoint used when a server reports
a version before 2.14.0, are defensive code, not a support promise.
Write-only attributes need Terraform or OpenTofu 1.11 or later. The native proofs
run with both tools; [TESTING.md](TESTING.md) records the tool versions used.

| Pocket ID | What depends on the version |
|---|---|
| 2.14.0 | The base. `public_keys` on federated identities, `backchannel_logout_url` and `auto_create_oidc_client_secret` are refused before any change. Pocket ID does not refuse images over 16 million pixels itself; the provider does. The `pocketid_clients` data source reports `allowed_user_groups` as null (use `pocketid_client`). |
| 2.15.0 | `public_keys` supported. Pocket ID refuses JPEG and PNG images over 16 million pixels. |
| 2.16.0 | As 2.15.0. |
| 2.17.0 | `backchannel_logout_url` and `auto_create_oidc_client_secret` supported; a new confidential client's server-created secret is revoked by the provider. |
| 2.18.0 | The icon library: `preset` on `pocketid_client_logo` and the `pocketid_logo_presets` data source. A client with only a dark logo shows it in light mode too. |

`pocketid_client_secret`, `pocketid_api` and `pocketid_api_client_access` need
Pocket ID 2.14.0 or later, which every supported server is. A feature that needs a
newer server than yours (`backchannel_logout_url`, `public_keys`,
`auto_create_oidc_client_secret`, a logo `preset`) is refused. CI runs the full provider and
data-source acceptance suites on 2.17.0 and 2.18.0 and every acceptance test family
(`make test-acc`) on 2.14.0, 2.15.0 and 2.16.0; `make test-acc-supported` runs the full
suites on all five and is part of the [release checklist](RELEASE_CHECKLIST.md).

## Upgrading from 2.4.x

3.0.0 is a major release because of deliberate breaking changes. Read the 3.0.0
section of [CHANGELOG.md](CHANGELOG.md), where each is marked **Breaking**, and run
a plan before applying. The ones most configurations meet:

- `pocketid_client.allowed_user_groups` is a set (also on the client data sources),
  so expressions that index into it need `tolist(...)`.
- `pocketid_client.client_id` is the client's real ID; a different configured value
  replaces the client. Removing `launch_url` no longer removes the URL (set `""`).
  Opening a restricted client needs `is_group_restricted = false`.
- Values Pocket ID would refuse fail at plan time: usernames, names, custom claim
  keys and values, one-time token lifetimes, application settings (an empty string
  for a setting with a default, `session_duration` below 1) and `is_public = true`
  with `pkce_enabled = false`. Identifiers that are not UUIDs (client IDs follow
  Pocket ID's own rule) are refused before any request is sent.
- Users created by the provider no longer receive Pocket ID's signup default
  groups and claims; list them in the configuration if you relied on them.
- The `pocketid_application_config` data source has no `smtp_password` or
  `ldap_bind_password`, and the resource no longer copies an unconfigured password
  into state.
- Go importers: the module is `github.com/irashack/terraform-provider-pocketid`.
  Configurations are unaffected.

[INSTALL.md](INSTALL.md#upgrade-from-24104-to-301) has the step-by-step upgrade, the
breaking changes to look for and the `-refresh=false` caveats. The state-compatibility
rule (Convention 5) is checked by the native upgrade scripts: they start from state
written by a published release, take it over with the new build and require an empty
plan. They are `tests/native/upgrade.py`, `client_upgrade.py`,
`upgrade_users_groups.py` and `application_config.py`; [TESTING.md](TESTING.md) says
what each proves and how to run it.

## Development and maintenance

Use the Go version in `go.mod`, Python 3 and Docker for disposable acceptance
tests. The test fixture chooses a free loopback port, seeds a fresh database, and
cleans up. It does not use your running Pocket ID instance.

```sh
make check                  # formatting, vet, unit/race tests, script tests, build and lint
make docs-check             # generated documentation matches the checkout
make test-acc               # every acceptance test family (TestAcc*) on Pocket ID 2.18.0
make test-acc-matrix        # the same on every fixture version (2.14.0 to 2.18.0)
make test-acc-provider      # full provider and data-source suites on POCKETID_VERSION (default 2.18.0)
make test-acc-supported     # the full suites on every supported version
```

[TESTING.md](TESTING.md) describes the checks, the fixture and the native
Terraform and OpenTofu proofs; [CONTRIBUTING.md](CONTRIBUTING.md) has the pinned
tooling and what a change must keep true; [RELEASE_CHECKLIST.md](RELEASE_CHECKLIST.md)
is the release procedure. Pull requests target `main-maintenance`.
[CI](https://github.com/irashack/terraform-provider-pocketid/actions/workflows/ci.yml)
checks changes, and releases are manually requested drafts. Dependabot groups
weekly dependency updates for review. Automatic development releases, scheduled
sweeps and contributor-edit jobs are not enabled.

Report reproducible bugs through [Issues](https://github.com/irashack/terraform-provider-pocketid/issues).
Use [private security reporting](SECURITY.md) for vulnerabilities. This is a
volunteer project with no response-time guarantee.

## Secret and failure behavior

Confidential-client creation generates one secret and keeps it in `client_secret`,
with its ID in `client_secret_id`. Public clients, and clients with
`generate_secret = false` (for use with `pocketid_client_secret`), generate none.
When Pocket ID 2.17.0 creates a secret of its own with a new client, the provider
revokes that one first, so the client keeps only the secret in state; a revocation
that cannot be confirmed is retried by the next apply, and the client's own secret
is not generated beside it. Only creating the client, changing `generate_secret` or
changing `is_public` generates or revokes a secret; refresh, import and other
updates do not. A refresh may read the client's secret metadata (IDs and prefixes,
never values) to fill in `client_secret_id`. Import cannot recover an existing
create-only secret; the value remains null. Store provider state securely; a
sensitive attribute alone does not encrypt state.

Version errors fail before creating a confidential client. Only Pocket ID's JSON
404 `API endpoint not found` identifies a missing version route. Invalid/empty
versions, authentication failures, unexpected 404s and server/transport failures
are not classified as old servers. Changes (create, update, delete, uploads) are
never retried automatically; reads are retried up to four attempts. HTTP redirects
are not followed with the API key.

A definite rejection can roll back only the object created in that operation, and
the provider says so only when it confirmed the deletion. Cleanup failure or an
ambiguous response retains the object's ID, and any generated secret, in state and
tells you to inspect read-only. **Do not blindly apply a tainted resource:**
Terraform may propose replacement. Inspect the object, then explicitly choose
recovery. No second secret is generated automatically. A user or client created
with a chosen ID whose creation had no definite answer is kept in state as
unresolved, and the provider refuses to change or delete it until you resolve it as
the error describes. A lost response to a server-generated-ID creation may leave an
object whose ID was never received; inspect the list before retrying. Existing-ID
conflicts do not trigger deletion. HTTP diagnostics expose status codes, not
response bodies, reason phrases or the text of malformed responses.
